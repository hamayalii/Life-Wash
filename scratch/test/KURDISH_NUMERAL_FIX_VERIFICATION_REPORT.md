## 3. Numeric Validation Enhancement

### Problem with `parseFloat()`

As you correctly noted, `parseFloat()` accepts partially numeric strings:
- `parseFloat("123abc")` → `123` (accepts invalid input)
- `parseFloat("12.34.56")` → `12.34` (accepts invalid input)

### Solution Implemented

Added `isValidNumericString()` function to `global-utils.js`:

```javascript
function isValidNumericString(value, allowNegative = false) {
  if (value === '' || value === null || value === undefined) {
    return false;
  }

  const converted = convertKurdishNumerals(value);

  // Regex validates pure numeric strings only
  const regex = allowNegative
    ? /^-?\d*\.?\d+$/  // Allows negative numbers
    : /^\d*\.?\d+$/;   // Only positive numbers

  return regex.test(converted);
}
```

**This rejects:**
- `123abc` ❌
- `12.34.56` ❌
- `abc123` ❌
- Empty string ❌

**This accepts:**
- `123` ✅
- `123.45` ✅
- `0.5` ✅
- `١٢٣.٥` (Kurdish) → converts to `123.5` ✅

### Validation Added to All Numeric Inputs

| File | Function | Validation Method |
|------|----------|-------------------|
| `dynamic-services.js` | `updateItemQuantity()` | `isValidNumericString()` + fallback |
| `pos.js` | `handleServiceFormSubmit()` | `isValidNumericString()` + fallback |
| `pos.js` | `customPriceConfirm` listener | `isValidNumericString()` + fallback |
| `report.js` | `updateAdSpend()` | `isValidNumericString()` + fallback |
| `report.js` | `addExpense()` | `isValidNumericString()` + fallback |
| `settings.js` | New service form | `parseFloat()` with explicit check |

**Fallback logic:** If `isValidNumericString` is not available (e.g., cached old version), the code falls back to `parseFloat()` to maintain functionality.
